## 2. 交付内容

### 2.1 放大弹窗 `[data-mh-modal]`

| 项 | 实现 |
|---|---|
| 入口 | 「原始响应」「请求详情」两档标题行的 **⛶ 放大**按钮（24×24）；模型文本档**不渲染** |
| 尺寸 | `80vw × 80vh`，实测 1707×735 视口下 = **1366×588（精确 80.0% / 80.0%）**，居中、四边不溢出 |
| 挂载 | `createPortal` 到 `document.body`；`require("react-dom")` 失败时回退就地渲染 |
| 关闭 | `Esc` / 点遮罩 / 点 ✕ 三种路径，关闭后焦点回到放大按钮 |
| 滚动 | 正文区是唯一可滚动区（`overscroll-behavior:contain`），打开期间锁 `body` 滚动 |

### 2.2 JSON 格式化

- **美化 / 原文**一键切换（`[data-mh-pretty]`，`aria-pressed` 表达态），缩进 **2 空格**。
- **只认对象与数组**：`JSON.parse` 接受裸标量（`"123"` → `123`），会把纯数字响应判成可美化并**剥掉引号改变语义**，故排除。
- 不可解析时**原样显示**并给出原因（悬停可见），不静默。
- **复制恒给原文**：美化只影响阅读，不影响复制内容。

### 2.3 请求详情的分块（用户特别强调的点）

用户明确指出请求详情**不是一个完整 JSON**。实测确认：三块拼接后 `JSON.parse` **必然失败**（已固化为断言 `V-C9`）。故按块建模、**各块独立判断**：

| 块 | 可美化 | 说明 |
|---|---|---|
| 系统提示 `sys` | 否 | 自然语言，如实标注「不是 JSON 对象或数组」 |
| 请求头 `headers` | 是 | 鉴权头已脱敏 `Bearer ***` |
| 请求体 `body` | 是（未截断时） | **被截断时**原因优先说「内容已截断，不是完整 JSON」 |

整档无任何可美化块时，「美化」按钮 `disabled` 并把原因放进 `title`——不会出现「点了没反应」。

### 2.4 计量

每块显示 `字符 · 行 · 字节`（UTF-8：中文 3 字节、代理对 4 字节）。块头计量描述**当前显示**的文本，弹窗头部计量描述**原文**并显式标注「原文」——美化后行数不同（1 → 15），不标注会被误认为算错。

## 3. 过程中发现并修复的两个真实缺陷

两个都是**只有渲染级测量才能发现**的（DOM 文本断言完全看不见）：

### 缺陷 1：弹窗 token 全部失效（预防性修复）

弹窗 portal 到 `body` 后**不在** `[data-mh-root]` 内。原 token 块挂在 `[data-mh-root]` 上，若直接 portal，弹窗内所有 `var(--mh-*)` 会失效（颜色/字号/圆角一起崩）。

**修法**：token 块选择器改为 `[data-mh-root],[data-mh-modal-overlay]`，与布局块拆开。
**固化**：`V-C8`（断言弹窗内 `font-size === '13px'` 而非默认 16px）+ 单测「token 选择器必须包含 overlay」。

### 缺陷 2：`width:80vw` 实际渲染成 **82.2vw**（实测发现）

`[data-mh-root] *{box-sizing:border-box}` 覆盖不到 portal 出去的内容，默认 `content-box` 让 `padding:14px 18px 16px` 加到宽度上。

**实测证据**：修复前 `modalRect = 1403×620`，`1707×735` 视口下 = **82.2% / 84.3%**；修复后 = **1366×588 = 80.0% / 80.0%**，`box-sizing === 'border-box'`。

**修法**：`[data-mh-modal-overlay],[data-mh-modal-overlay] *{box-sizing:border-box}`。
**固化**：`V-C7` + 单测「overlay 子树必须自带 box-sizing」。
